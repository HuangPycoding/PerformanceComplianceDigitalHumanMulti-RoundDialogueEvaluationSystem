关于系统

美团外呼对话模型评测系统 — 对 LLM 对话模型进行全流程自动化多维度评测。项目源码 ~17,800 行 Python，包含五大引擎。

一、用户画像生成器

基于 15 维参数空间（大五人格 5 维 + 对话行为 4 维 + 认知 2 维 + 情绪 2 维 + 对抗 2 维），通过 8 阶段管线生成多样化用户画像：

阶段方法说明
P1LHS 全空间采样拉丁超立方采样在 [0,1]^15 均匀覆盖，默认 5 个全局样本
P2子空间 LHS解析 Case 分支条件 → 映射到维度约束子空间 → 每个分支 2+N 样本（N 随复杂度递增）
P3对抗策略自动挂钩根据维度值自动判定（探针型/注入型/矛盾型/权威型/情绪型），覆盖 50% 画像
P4锚点翻译15 维 × 5 锚点 = 75 行为锚点文本，取最近锚点 + 标注偏离度
P5CO-STAR 框架Context/Objective/Style/Tone/Audience/Response 结构化 prompt
P6Contrastive Prompting排除法对比：极端维度标注"你不是这样的"
P7自检回路LLM 独立重打分 → 欧氏距离 d_sv 验证 → 偏离超阈值则锚点修正重试（默认 3 次）
P8画像追踪回溯原始采样值(sampled_vector) + LLM 验证值(verified_vector) + 审计值(audited_vector) 三向量存档

二、评测引擎 — 三层体系

层级方法输出
Tier 1 — 规则引擎11 个可计算指标，零 LLM 成本。约束分流（word_limit/forbidden_word/tone/safety/behavior/other）、Call Flow 步骤覆盖检测、开场白匹配、对话轮次效率硬性扣分 + surface_compliance_flags
Tier 1.5 — 信号提取7 个 Turn 级信号提取：情绪曲线/模型行为/对话质量/风险标记/should_end 等。从对话 XML parsed_tags 解析清单生成器输入
Tier 2 — LLM Judge9 维度独立并发核查。结构化清单 = Case 指令清单 + Simulator 信号清单 + LLM 补充清单。ConcurrentJudgeRunner（AIMD 流控 + CircuitBreaker 熔断）每维度 YES/MOSTLY_YES/PARTIAL/MOSTLY_NO/NO/NA 六级

9 评测维度

维度名称权重SCOPE检查内容
SAFETY安全合规2.0是(封顶50)身份核实、敏感信息处理、合规声明
TASK_COMPLETION任务完成度1.8是(封顶60)Call Flow 步骤逐项覆盖、必要信息传递
FLOW_COVERAGE流程覆盖1.2否分支覆盖率、步骤跳转合理性
CONSTRAINT约束遵守1.0否字数限制/禁止词/语气/行为约束逐条检查
KNOWLEDGE知识点运用1.0否FAQ 准确度、知识点调用时机
EFFICIENCY交互效率0.9否轮次数、冗余度、信息密度
ROLE角色扮演0.8否客服身份一致性、话语风格
SENTIMENT情感处理0.8否情绪识别准确度、共情回应质量
OPENING开场白0.5否开场白完整性、信息覆盖

评分体系

五级评级：卓越(≥90) / 良好(≥70) / 合格(≥50) / 需改进(≥30) / 不合格(＜30)

SCOPE 一票否决：SAFETY 不合格 → 总分封顶 50；TASK_COMPLETION 不合格 → 总分封顶 60

EvalConfidence：20+ 因子可信度计算（checklist_signal_consistency / signal_conflict_count / evidence_empty_ratio / avg_evidence_coverage / simulator_tier / signal_weight_factor / meta_check_alerts），Meta Check 最大总惩罚 0.08

三、优化引擎 — 双路径架构

路径方法特点
Path A — 规则引擎bigram 文本聚类 + 相似度分组 → 优先级 = 严重度 × 维度权重 × 频次 × 置信度。评分分布异常检测、信号矛盾检测（规则-LLM 交叉验证）、Meta Check 覆盖度分析零 LLM 成本、100% 可复现
Path B — LLM 深度分析DSPy MIPROv2 批量候选生成(N=5) → OPRO 优化轨迹存储历史 → Constitutional AI 三段式输出（宪法原则→违规证据→批判分析→修正建议）→ TextGrad 文本梯度归因（AttributionItem 逐项反向传播）→ MMR 多样性感知 Few-shot(λ=0.7)需要 LLM、含具体修改文本

四对象优化目标

Case 定义call_flow 步骤调整/分支完善/reference_script 更新/constraint 阈值放宽或收紧/knowledge_points 补充
用户画像生成器参数分布调整/自检阈值优化/锚点描述修正/对抗策略触发条件/CO-STAR prompt 模板改进
被评测对话模型system_prompt 改写/few-shot 示例补充/输出格式约束/temperature 调整建议
评测引擎自身清单项增减/维度权重校准/Judge prompt 改进/置信度因子调整/交叉验证阈值

四、对话模拟引擎

被评测模型 (LLMAssistant) 与模拟用户 (UserSimulator) 进行多轮外呼对话。输出 8 种 XML 解析标签：thought / memory / state / emotion_curve / model_behavior / conversation_quality / risk_flag / should_end。支持对话结束检测（LLM 判断 + 关键词回退）、模型崩溃检测（R7 连续 2 次质量故障触发）、对话超时自动挂断。

五、数据流全景

Case 文本 → parse_instruction() 纯函数解析 → Case 对象 → 画像生成(ProfileGenerator) → 对话模拟(DialogueRunner) → 评测(EvalOrchestrator) → 优化(OptimizationEngine) → 报告(DataExporter)

所有中间数据均可导出：profiles.json(画像) / conversation_*.json+md(对话) / evaluation_*.json(评测) / optimization_feed.json(优化输入) / optimization_report.md(优化报告)
